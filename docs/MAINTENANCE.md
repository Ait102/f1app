# Поддержка F1 Season Hub (этап 7 SDLC)

## Что проверяется автоматически

| Что | Когда | Где |
| --- | --- | --- |
| Unit- и E2E-тесты, сборка | каждый пуш в `main` | `.github/workflows/ci.yml` |
| Живой API Jolpica: доступен ли, не изменился ли формат JSON | каждый понедельник 06:00 UTC и вручную | `.github/workflows/api-health.yml` → `npm run test:contract` |

Если еженедельная проверка падает, в репозитории автоматически открывается issue «API Jolpica: проверка не прошла» со ссылкой на лог. Повторные сбои добавляются в тот же issue комментариями.

Запустить проверку вручную: **Actions → API health check → Run workflow**, или локально:

```bash
npm run test:contract
```

## Если проверка упала

1. Откройте лог из issue и посмотрите, какая проверка не прошла. Сообщения написаны по-русски: например, «маппер отбросил часть этапов — формат календаря изменился».
2. **HTTP 5xx, тайм-аут или сеть** — скорее всего, временный сбой Jolpica. Перезапустите проверку через пару часов. Сайт в это время показывает сохранённые данные с предупреждением.
3. **HTTP 429** — лимиты стали строже. См. раздел «Лимиты».
4. **«Маппер отбросил…» или «не разобраны»** — изменился формат JSON. Сравните ответ API с разбором в `src/domain/mappers.ts`, поправьте маппер, добавьте unit-тест на новый формат.
5. Проверьте новости API: https://github.com/jolpica/jolpica-f1 (Releases, Discussions).
6. Закройте issue после исправления.

## Стили

Один файл `src/styles.css`: токены (цвета, отступы, тайминги) в `:root`, дальше правила по блокам страницы.

Правило: не добавляйте новое правило для селектора, у которого уже есть объявления ниже в файле, — правьте существующее. Раньше в файле лежали два слоя, где второй перекрывал первый; перекрытые объявления вычищены, и при правках достаточно смотреть на одно место. Проверять визуально удобнее скриншотами: `npx playwright test` со `toHaveScreenshot` на временном спеке (в репозиторий его не кладём — базлайны зависят от ОС).

## Лимиты API

Сейчас без токена: 4 запроса/с, 500 запросов/ч. Jolpica предупреждает, что лимиты будут снижаться.
В коде:
- `minIntervalMs` в `src/api/client.ts` — минимальная пауза между запросами (сейчас 260 мс ≈ 4/с);
- `ttlMs` там же — сколько минут держать ответ в кэше (сейчас 10). Увеличение кэша — первый способ уменьшить нагрузку;
- самая тяжёлая страница — «График»: по одному запросу на каждый завершённый этап.

Если Jolpica введёт токены, ключ нельзя класть во фронтенд (требование ТЗ) — понадобится серверный прокси.

## Схемы трасс

Контуры трасс, длина, число поворотов, направление движения и годы, в которые конфигурация использовалась, — статические данные из [F1DB](https://github.com/f1db/f1db) (CC BY 4.0), не из API.

Устроено так:

- `scripts/build-circuits.mjs` выкачивает YAML и SVG из F1DB и пишет `src/data/circuits/map.ts` (Jolpica `circuitId` → slug F1DB) и `src/data/circuits/shapes/<slug>.ts` — по файлу на трассу, в каждом все её конфигурации с годами (`eras: [[1997, 2009], …]`, `9999` означает «по сей день»).
- `loadCircuit(circuitId, season)` подтягивает нужный файл через `import.meta.glob` (каждая трасса — отдельный чанк 1–12 КБ) и возвращает конфигурацию, действовавшую в этом сезоне.
- Нет трассы в маппинге, нет конфигурации на этот год или год подходит сразу к нескольким — блок «Схема трассы» не показывается вовсе.

Добавить трассу: строку `'jolpica_id': 'f1db-slug'` в `MAP`, затем

```bash
node scripts/build-circuits.mjs
npm test && npm run build
```

`src/components/CircuitMap.test.tsx` проверяет, что геометрия есть для всех трасс сезона и что для разных сезонов выбираются разные конфигурации (Монца 1950 / 1955 / 2026, Сильверстоун 1998 / 2012).

## Исправления результатов
Источник сам обновляет результаты после протестов и штрафов. Приложение подхватывает изменения максимум через 10 минут (кэш) или сразу по кнопке «Обновить».
Раз в несколько этапов повторяйте сверку с formula1.com, как описано в `docs/TESTING.md`.

## Ошибки от пользователей

Принимаются через GitHub Issues. При разборе: какой сезон и страница, что показано на сайте и что ожидалось, совпадает ли это с ответом API (ссылка «Источник» под каждым блоком данных).

## Обновление зависимостей

Раз в месяц или по уведомлению о безопасности:

```bash
npm outdated
npm update
npm test && npm run test:e2e && npm run build
```

Мажорные версии (React, Vite, Vitest, Playwright) обновлять по одной, с полным прогоном тестов.
